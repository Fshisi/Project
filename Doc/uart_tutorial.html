1设计目标

  • 自包含：只依赖 main.h（HAL/CMSIS）和 stdio.h，不依赖 CubeMX、不依赖工程其它文件。
  • 宏适配区：换串口号 / 波特率 / 引脚，只改 uart.c 顶部一组宏，函数体不碰。
  • 发送双通道：阻塞版 SendStr（printf 走这条路）+ 中断版 SendStr_IT。
  • 接收双中断：RXNE 逐字节收进环形缓冲；IDLE 空闲中断判定"不定长一包结束"，主循环批量消费。
  • 错误自恢复：ORE 等接收错误后自动重挂接收链，不会"永久失聪"。
本文档整理的是教程模板原版代码。工程内 User/Drivers/uart.c 是在此基础上的改版，两者若有出入，以工程实际文件为准（当前工程版已知差异见第 12 节末尾）。

串口没有时钟线，双方事先约好速度（115200）和格式（8-N-1）靠约定对齐。空闲时线保持高电平；起始位用一个低电平"喊话"，随后 8 个数据位按低位在前依次发，最后停止位拉高收尾。下图是发送 0x55（二进制 01010101）的波形——0/1 交替翻转，最直观：

3波特率怎么算（用本工程真实时钟）

USART1 挂在 APB2 上（注意和 TIM3 的 APB1 不同）。本工程时钟链：SYSCLK 64MHz → AHB ÷1 → APB2 ÷1 → PCLK2 = 64MHz，这就是 USART1 的计时钟。硬件要求分频值 USARTDIV = fck ÷ (16 × 波特率)：

USARTDIV = 64MHz ÷ (16 × 115200) = 34.72
整数部分 34，小数 0.72 × 16 ≈ 11  →  BRR = 34×16 + 11 = 555
实际波特率 = 64MHz ÷ (16 × (34 + 11/16)) ≈ 115207，误差 +0.006% ✓

串口允许 ±2% 误差，0.006% 非常稳。好消息：这些全是 HAL_UART_Init 内部自动算的，你只填 BaudRate = 115200U。HAL 自动从 RCC 取 PCLK2，时钟配置改了它跟着变，不会算错。

4学 HAL 外设 = 记住"五件套"

和 tick.c（TIM3）完全同构，只是换了外设。学会这一套，SPI、ADC、CAN 都是照葫芦画瓢：

tick.c（TIM3）uart.c（USART1）职责
htim3 句柄huart1 句柄全局唯一，中断/回调都通过它访问
Tick_Init() 填结构体UART1_Init() 填结构体填 Init 子结构体 → 调 HAL_xxx_Init
HAL_TIM_Base_MspInitHAL_UART_MspInit自动回调：时钟使能 + 引脚（+开中断时配 NVIC）
TIM3_IRQHandlerUSART1_IRQHandler只有开中断才需要；覆盖启动文件弱符号
HAL_TIM_PeriodElapsedCallbackHAL_UART_RxCpltCallback / TxCpltCallbackHAL 干完活通知你，业务写这里

Init 流程都一样：HAL_UART_Init 内部先回调你的 MspInit（时钟/引脚就位），再写 USART 寄存器（含自动算 BRR）。发送方向再加一环：printf → fputc（重定向）→ HAL_UART_Transmit → 引脚。

为什么阻塞发送是调试串口的正确默认值：两种发送方式总耗时一样（115200 下每字节 8.68µs），中断发送省的只是 CPU 等待，代价是缓冲区生命周期、重入、竞争三件套。printf 链路逐字符同步出口，和 IT 发送天然不兼容。出现"波特率上 460800+ 或单次发几 KB"的证据再升级，不要预防性升级。

7接收链路：两条中断通路汇合到主循环

  

  
  

  
接收链是"预订—回调—续订"模式，全工程挂接只有三处

  

    
位置角色时机

    
UART1_Init 里的 HAL_UART_Receive_IT(&huart1, &s_rx_byte, 1U)点火上电一次：登记缓冲指针 + 使能 RXNEIE + 状态置 BUSY_RX。不挂这第一个，RXNE 中断永远不会来

    
HAL_UART_RxCpltCallback续棒每收 1 字节：入环形缓冲，再 Receive_IT 挂下一个

    
HAL_UART_ErrorCallback救火出错（ORE 等）后 HAL 停止续挂，必须手动重挂恢复接收链

  

  
&s_rx_byte + 1U 的含义：HAL 要求缓冲区活到回调发生（中断是异步的），所以落脚点必须是文件级静态变量，传栈上局部变量的地址是经典 bug；一次预订 1 字节是"不定长接收"最灵活的挂法。






  
8四个关键机制（都是实际翻车点）

  
    
    
  1. IDLE 中断 HAL 完全不管。HAL 的 HAL_UART_IRQHandler 里没有 IDLE 分支——使能（__HAL_UART_ENABLE_IT(&huart1, UART_IT_IDLE)）和查清都要自己做。IDLE 的含义：收到数据后，线上空闲超过 1 字节时间（115200 下约 87µs）硬件自动置位——它就是"不定长一包结束"检测器。本 HAL 包里 __HAL_UART_CLEAR_IDLEFLAG 是完整的"读 SR + 读 DR"清除序列（已验证 hal_uart.h 504-510 行）。
    2. 
    
  2. IRQHandler 里的顺序不能反。清 IDLE 的宏要读 DR。如果 IDLE 置位时恰好 RXNE 也挂着（新字节在 DR 里还没被 HAL 收走），先清 IDLE 就会把那个字节偷走——丢数据还打乱 HAL 状态机。固定顺序：先 HAL_UART_IRQHandler，再查清 IDLE。
    3. 
    
  3. ErrorCallback 不写，接收链会"永久失聪"。发生 ORE 溢出（主循环没来得及消费、对方还在发）等错误后，HAL 会停止续挂单字节接收——不手动恢复，串口从此收不到任何东西。这是 HAL 单字节接收最隐蔽的坑。
    4. 
    
  4. 中断/主循环共享的三个变量必须 volatile（s_rx_head、s_frame_flag、s_rx_over）——中断写、主循环读，缺了 volatile 编译器可能优化掉重复读取。
    5.

11坑清单

  
    
    
  1. TX/RX 引脚方向不对称：F1 上 TX 必须 GPIO_MODE_AF_PP（复用推挽），RX 用 GPIO_MODE_INPUT 浮空。不要套用 F4 的"两个都配 AF"思路——F1 HAL 的输入脚就是普通输入模式。
    2. 
    
  2. 阻塞 HAL_UART_Transmit 的 pData 无 const——和 hw_i2c.c 那次 Keil #167 一模一样的坑，模板里已转好 (uint8_t *)s。而新版 HAL 的 Transmit_IT 形参带 const，不用强转。
    3. 
    
  3. 中断服务函数里禁用 printf：阻塞 + 非可重入，双重危险。
    4. 
    
  4. USART1_IRQHandler 全工程只能定义一份：uart.c 里定义后，stm32f1xx_it.c 里不能再出现同名函数（L6200E）。
    5. 
    
  5. SendStr_IT 与 printf/fputc 共用发送状态机：同一时刻只能一路在发，后调的返回 HAL_BUSY（SendStr_IT 表现为返回 1 丢弃本次）。
    6. 
    
  6. 换串口号三件套成对改：UART_INSTANCE / UART_IRQn / UART_CLK_ENABLE()，且 USART1_IRQHandler 函数名要手动同步改（函数名没法宏化）。
    7. 
    
  7. HSI 精度 ±1%：本工程 HSI+PLL 出 64MHz，对 115200 依然够用（±2% 门限）；换 HSE 后 HAL 自动跟 RCC 走。
    8.
