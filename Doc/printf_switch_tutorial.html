printf 总开关教程（ESP32 风格）

一个宏开关控制全工程日志：开着正常输出，关掉整机静默——代码里的 printf 一个都不用注释、不用删

适用工程：TC300PGS（Keil AC5 · HAL 库）· 整理自 2026-11-19 对话教程 · 三种方法均给出可直接粘贴的代码
目录： 1 原理 2 方法一 fputc 开关 3 方法二 LOG 宏 4 方法三 分级日志 5 开关放哪 6 坑清单 7 选型对照

01原理：裁剪发生在"预处理"阶段

ESP32（ESP-IDF）的 ESP_LOGI/ESP_LOGE 之所以能"一个开关全静默、代码不用动"，是因为日志调用不是函数调用，而是宏——开关在编译之前的预处理阶段就把代码裁掉了。你的 Keil 工程用同样的机制就能做到一模一样的事。

下文三种方法按"离 ESP32 的远近"排列：方法一只堵出口、改动最小；方法二是 ESP32 的真正等价物；方法三是 ESP-IDF 分级日志的完整复刻。

02方法一：fputc 总开关（程序里写的 printf 一个都不用碰）

Keil（ARMCC）下所有 printf 最终逐字符经过你重定向的 fputc——把开关装在这里，全工程任何地方写的 printf 都不用改一个字：开关关掉，printf 照常执行但不再输出。你的 uart.c 目前还没有 fputc，正好从零加上。

你工程 uart.c 里已有 #include <stdio.h>、huart1 和 UART_TX_TIMEOUT_MS（100U），这段代码直接粘贴即可编译——单字符超时复用 100U 完全够用。

  
方法一的开关是"堵出口"：printf 的格式化计算照常发生（CPU、栈、字符串常量都还占着），只是结果不出门。调试期临时静音够用；要真·零开销看方法二。







  
03方法二：LOG 宏（ESP32 的真正等价物，编译期整行删除）

  
把日志调用写成宏 LOG(...) 而不是裸 printf。开关关掉时，整条调用连参数一起在预处理期消失——不占 CPU、不占 ROM，这才是 ESP32 ESP_LOGx 的完整机制。你的工程还没开始写 printf，从第一天就用 LOG 是最划算的。


  

    
    
    

  


  
为什么关掉后是 ((void)0) 而不是定义成空？

  
    
    
  • LOG("a"); 关掉后展开为 ((void)0);——一条合法的空语句，if (x) LOG("a"); else y(); 这种不带花括号的写法也不会语法错误
    • 
    
  • 若定义成完全展开为空：if (x) else y(); 直接编译报错
    • 
    
  • 若改成"return 前清零"式写法都轮不上——宏展开发生在编译前，((void)0) 就是让编译器"看见一条无害的空语句"
    • 
  

  
副作用警告（ESP32 官方文档同样提示）：开关关掉时，参数表达式不会被执行。LOG("temp=%d\r\n", ReadTemp()); 关闭后 ReadTemp() 不再被调用！如果某行日志"顺便"触发了你要的副作用（读传感器、翻标志），关日志会改变程序行为——副作用请写在日志外面。







  
04方法三：分级日志（ESP-IDF ESP_LOGI/ESP_LOGE 同款）

  
正式项目长期维护用这套：错误和信息分级，一个数字控制"哪些级别放行"。LOG_LEVEL 从 0 升到 2，日志逐渐"打开"；将来板上空间紧张就降回 0，全部消失。


  

    
    
    

  


  
"[E] " 和后面的格式串靠 C 的字符串字面量自动拼接合成一个字符串——所以 LOG_E 的第一个参数必须是 "..." 字面量（和 ESP32 的 ESP_LOGE(TAG, "...") 同样的限制）。







  
05开关放哪里 + Keil 里"不改代码"也能关

  
开关宏必须放在头文件里（uart.h），因为 main.c 等所有调用方都要看见它。再配一层 #ifndef 保护，就能在 Keil 的编译选项里覆盖开关——一行源码都不改就能切换开/关，这正是 ESP32 menuconfig 的精神：


  

    
    
    

  


  
Keil 里覆盖：Options for Target → C/C++ → Define 栏，在已有宏后面追加（注意 Keil 用逗号分隔、不带 -D）：

  

    
STM32F103xB,USE_HAL_DRIVER,LOG_ENABLE=0

  

  
    
    
  • 这样处理后，源码里的默认值让位给编译选项——调试版/发布版可以做成两个 Target（比如 TC300PGS 开日志、TC300PGS_Release 关日志），切 Target 就切日志，源码永远不动
    • 
    
  • 没有这层 #ifndef 时，编译选项里的定义会和源码里的 #define 冲突告警（宏重定义）
    • 
    
  • 如果 AC5 在 C90 严格模式下对 __VA_ARGS__ 报错：Options → C/C++ → 把 C 标准选成 C99（或保持默认的 GNU 扩展模式）
    • 
  







  
06细节与坑清单

  
    
    
  1. 方法一关掉 ≠ 零开销：printf 的格式化（解析 %d、%u、除法求余）照常执行，只是结果不出门。程序跑得慢的时候，静音版日志照样吃 CPU——要省，用方法二/三的编译期删除
    2. 
    
  2. 编译期删除会删掉参数副作用：LOG("x=%d", GetX()) 关闭后 GetX() 不执行。需要保证执行的调用写在 LOG 外面，别藏在日志参数里
    3. 
    
  3. 别用 #define LOG(...) 展开为空：if (x) LOG("a"); else y(); 会变成 if (x) else y(); 语法错误。必须展开为 ((void)0)
    4. 
    
  4. printf 系列从未接到串口时：没勾 MicroLIB 也没实现 fputc，printf 会走半主机模式（semihosting）卡死或 HardFault——Options → Target → 勾 Use MicroLIB + 本文的 fputc，两件都要有
    5. 
    
  5. LOG_E/LOG_I 首参必须是字面量："[E] " __VA_ARGS__ 靠字面量拼接，传变量名进去直接编译错误（这是刻意的，防手滑）
    6. 
    
  6. 换 GCC 工程时：ARMCC 走 fputc，GCC（如 STM32CubeIDE）走 int _write(int fd, char *ptr, int len) 重定向——本教程 Keil AC5 场景不涉及，换工具链时记得换挂点
    7. 
  







  
07三种方法怎么选 + 接入你的工程

  

    
对比项方法一 fputc 开关方法二 LOG 宏方法三 分级 LOG

    
已有的 printf 调用一个都不用改要把 printf 换名成 LOG要换成 LOG_E / LOG_I

    
关闭后的 CPU 开销仍有格式化开销0（整行删除）0（整行删除）

    
关闭后的 ROM 占用格式化代码仍在00

    
开关粒度全局一个全局一个按级别（0/1/2…）

    
离 ESP32 的远近只是"静音"机制完全相同机制 + 分级都相同

    
适合现成代码、调试期临时静音新代码从第一天就用正式项目长期维护

  


  
接入 TC300PGS 的三步

  
    
    
  1. uart.h：粘贴第 2/3/4 节的开关宏（推荐直接上方法三的分级版，把 LOG_ENABLE 那段换成带 #ifndef 的版本）
    2. 
    
  2. uart.c：粘贴方法一的 fputc（它是 LOG 打开时的物理出口，两者配合：fputc 挂串口、LOG 管开关）
    3. 
    
  3. main.c：初始化后试一行 LOG("hello, %u ms\r\n", HAL_GetTick());，串口助手 115200-8-N-1 看心跳；然后去 Keil 的 Define 里加 LOG_ENABLE=0 再编译——什么都不改，串口就该安静了
    4. 
  

  
记住分工：fputc 负责"日志从哪出去"，LOG 宏负责"日志生不出生"。两个开关叠用，就是 ESP32 的完整体验——写代码时随手 LOG，交付前一个宏全静默，一行源码都不用回改。
